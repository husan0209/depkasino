и какие отступления сделаны осознанно. Ссылки на § — по нумерации ТЗ (Часть 5) и дизайн-сборки (Часть 5.1).

## 1. Проверено автоматически

Всё ниже прогоняется одной командой — `npm run acceptance` (нужен запущенный `npm start` или `npm run dev`).
Последний прогон: **115 проверок, 0 провалов**, повторный запуск — тоже зелёный.

**Сборка и типы**

- `npx tsc --noEmit` — 0 ошибок.
- `npm run build` — успех: 79 маршрутов, SSG `/casino/[slug]` × 40 и `/providers/[slug]` × 12, shared JS 87.3 kB.
- `npm run lint` (`next lint`) — без предупреждений.
- Оптимизатор `next/image` отдаёт каверы и логотипы: `/covers/*.svg` и `/providers/*.svg` → 200 `image/svg+xml`.

**Денежные форматы (§2.5)** — `scripts/format-suite.ts`, 27 правил, ожидания сверяются посимвольно
(включая неразрывный пробел-разделитель и типографский минус):

**Полный денежный путь через мок-API**

1. вход → кошельки `RUB 1200 / KZT 8200 / USDT 150 / UAH 0 / BYN 0 / UZS 0 / BTC 0` — отдельными записями, без «итого»;
2. депозит 1500 ₽ через СБП → статус `completed` по факту платежа → RUB 2700, транзакция `deposit · completed`;
3. вывод при `not_started` KYC → `403 kyc_required` (стоп до верификации);
4. KYC-заявка → `on_review` → модерация → `approved`;
5. вывод 500 ₽ → `201`, RUB 700, транзакция `withdrawal · processing` с реквизитами;
6. крипто-депозит USDT → адрес сети TRC20, срок 30 минут; BTC-депозит зачисляется по факту платежа с сетевой комиссией;
7. история ставок: фильтр по валюте возвращает только эту валюту (KZT ≠ RUB);
8. поддержка: тикет создан, ответ добавлен, закрытие работает;
9. реферал: код, приглашённые, начисления по валютам, вывод бонуса `201`;
10. избранное: добавление → список; запуск: `RUB` → `/play`, `UZS` → `422 currency_not_supported`, `demo` без авторизации работает.

**Содержимое SSR и запреты (§24)**

- Главная: герой с одним CTA, колода, «Популярное сейчас», «Новые игры», «Провайдеры», блок «Для новых игроков» — в HTML.
- Каталог: фильтры из URL, сетка, «Найдено N», обложки; `?q=bonanza` реально фильтрует; `?category=new&sort=new` тоже.
- Карточка игры: название, провайдер, RTP, волатильность, мин. ставка, «Играть»/«Демо», избранное, похожие.
- Таб-бар: «Главная · Казино · Избранное · Профиль» (без сокращений), кошелька нет.
- Футер: 18+, «Ответственная игра», документы, «Способы пополнения» по гео.
- В коде и в HTML нет: `≈`, «Итого», «Избр.», GGR/ledger, светлой темы, мультиязычности, live-чата, WebSocket,
  обязательной страницы-шлюза, двух кнопок «Играть/Демо» на мобильной карточке. RTP/волатильность — только в карточке игры и превью.
- `FEATURE_FLAGS`: `FEATURE_PROMOCODE`, `FEATURE_BONUS_PAGE`, `FEATURE_WAGERING`, `FEATURE_PROMO_SLOT` — все `false`.
- В реестре валют ровно 7: RUB, UAH, BYN, KZT, UZS, USDT (TRC20), BTC. Пресеты депозита — только фиат + USDT, у BTC пресетов нет.

**Первый кадр (SSR + подсказка сессии)**

- SSR всегда отдаёт витрину гостя — поисковик и новый игрок видят контент мгновенно.
- Inline-скрипт до отрисовки ставит `data-session` на `<html>` по наличию токена, а CSS прячет чужое:
  «своему» не показывается маркетинговый герой и блок «Для новых игроков» (вместо героя — скелет «Продолжить играть»),
  гостю не показываются служебные скелеты и заготовка аватарки в табе «Профиль».
- Первый клиентский рендер совпадает с серверным (замеры разметки сходятся), поэтому нет hydration-ошибок:
  `window`/`localStorage` читаются только в эффектах и обработчиках (`session-hint`, `useMounted`).

## 2. Что нужно посмотреть глазами

В этой среде нет браузера, поэтому интерактив и вёрстка проверены только чтением кода и SSR-разметки.
Ручной сценарий (телефон 360–430 px, тёмная тема):

1. `/` гостем: герой, колода, «i» на карточке, тап по обложке → запуск; «Играть сейчас» → каталог.
2. `/casino`: чипы, поиск с debounce, фильтры в URL (обновление страницы сохраняет фильтры), infinite scroll до «Больше игр нет».
3. Карточка игры: «Играть» гостем → `LoginSheet` → после входа запуск продолжается в один шаг; «Демо» — без авторизации.
4. Касса: депозит фиатом → статус опрашивается, баланс обновляется, «Вернуться в игру» появляется после закрытия кассы.
5. Кошелёк: переключатель валют (Фиат/Крипта, тусклые нули внутри групп), смена активной валюты, `/wallet/transactions` с фильтрами.
6. Вывод: при `not_started` — один экран-стоп с кнопкой «Пройти верификацию»; после `approved` — форма, `ConfirmModal`, заявка.
7. KYC: шесть состояний через `POST /api/v1/dev/kyc`, включая `rejected` с причиной и повторную отправку.
8. Колода: свайпы влево/вправо, драг вверх не ломает скролл, клавиатура ←/→, финальная карта ведёт в каталог.
9. Проверить, что тост «Вернуться в игру» не появляется при входе в игру без похода в кассу (исправлено).
10. Консоль браузера: не должно быть предупреждений о hydration и ошибок React.

**Логика запуска (§8.2)** — `scripts/launch-suite.ts`, 14 сценариев на чистой функции `lib/launch-decision`:
гость получает вход, а не редирект; повторный заход идёт в знакомую валюту; активный непустой кошелёк
играет без вопросов; пустой активный предлагает ненулевую валюту (при равных условиях фиат важнее крипты);
неподдерживаемая валюта не конвертируется, а честно останавливает запуск; пусто везде — касса активной валюты.

**SEO-слой**

- `robots.txt` закрывает `/wallet`, `/profile`, `/history`, `/kyc`, `/support`, `/referral`, `/favorites`, `/play`
  и авторизацию; `sitemap.xml` содержит 57 публичных адресов (6 разделов + 39 игр + 12 провайдеров), без дублей.
- Приватные страницы дополнительно несут `noindex`, витрина — `index`, каталог — `canonical`, `<html lang="ru">`.
- На карточке игры JSON-LD: `BreadcrumbList` из четырёх шагов и `SoftwareApplication` с описанием RTP
  и `Offer` по минимальной ставке; на странице провайдера — крошки.
- OG-картинки 1200×630 отдаются по тому же адресу, что стоит в `og:image`; шрифт с кириллицей лежит в репозитории
  (`src/assets/fonts`, лицензия рядом), поэтому сборка не зависит от сети.

**Состояния ошибок и пустоты**

- Единый компонент `QueryError` («Не загрузилось» + «Повторить») стоит в колоде, избранном, превью игры, KYC и реферальном кабинете:
  вечного скелета на упавшем запросе нет нигде.
- Тикет с несуществующим id больше не крутит скелет бесконечно — «Тикет не найден» + возврат к списку.
- Каталог при ошибке даёт `EmptyState` с повтором, конец списка подписан «Больше игр нет».
- Пустые состояния: избранное («Пока пусто» + каталог + 6 популярных), поиск (подсказки + похожие), кошелёк
  (нулевой баланс → «Пополнить»), вывод (пустой кошелёк → предложение ненулевой валюты).

**Live-режим API проверен вживую**

`NEXT_PUBLIC_API_MODE=live` до этой проверки не запускался ни разу. Собрал отдельную копию с
`NEXT_PUBLIC_API_URL=http://localhost:3000/api/v1` (мок-API по HTTP) и поднял на :3200:

- все публичные страницы отвечают 200, данные реально приезжают по сети (колода, сетка каталога, RTP 96,48%);
- значит ветка `liveFetch` в `lib/data/catalog.ts` и серверные контракты Частей 2–4 совпадают с моком.

**Границы ошибок (§23 блок I)**

- `app/error.tsx` — «Экран не открылся» + «Повторить» без потери адреса, с кодом обращения для поддержки;
- `app/global-error.tsx` — последний рубеж для сбоя корневого layout, со своими инлайновыми стилями
  (чужой CSS там может быть недоступен);
- `(main)/loading.tsx` — скелетон перехода между разделами вместо пустого экрана.

Проверено имитацией сбоя в отдельной live-сборке: сервер отдаёт 500 и подключает чанк границы
(`error-*.js` с нашим текстом, `global-error-*.js`); сама отрисовка происходит на клиенте после гидратации —
это штатное поведение Next, полноценно увидеть её можно только в браузере.

**Защита от опасной конфигурации**

Если включить `NEXT_PUBLIC_API_MODE=live` и забыть адрес API, клиент ушёл бы на собственный `/api/v1`,
где в сборке лежит мок — на продакшене это выглядело бы как настоящие балансы и платежи. Теперь сервер
при старте пишет предупреждение, а приёмка проверяет, что эта защита на месте.

**Визуальная проверка headless-браузером**

Браузера в среде нет, но его можно поднять: пакет `@sparticuz/chromium` (npm) приносит сам Chromium
и набор библиотек Amazon Linux (`al2023.tar.br`), из которого достаём недостающие системе
`libnspr4/libnss3/libnssutil3`; шрифты с кириллицей кладём в каталог fontconfig. Дальше —
`puppeteer-core` и скриншоты 390×844 (тот самый приоритетный диапазон ТЗ).

Рецепт воспроизведения (вне репозитория, чтобы не тащить браузер в зависимости):

```bash
npm i puppeteer-core @sparticuz/chromium   # в отдельной папке
node -e "zlib.brotliDecompressSync(...)"   # распаковать al2023.tar.br и swiftshader.tar.br
LD_LIBRARY_PATH=<папка с lib> FONTCONFIG_PATH=<папка с fonts.conf> node shot.mjs <url> <out.png>
```

Снимки-свидетельства лежат в `docs/preview`: `ui-home-390.png`, `ui-casino-390.png` и пара
`ui-before-*` — как выглядело до «спокойного прохода».

**Спокойный проход по дизайну (§5.1)**

Первая же визуальная проверка подтвердила замечание о «кислотности»: две причины.

1. **Неоновые ореолы у логотипа и кнопки депозита.** Именованные тени `shadow-accent` и
   `shadow-money` совпадали по имени с цветами палитры — Tailwind в этом случае генерирует второе
   правило `shadow-*` и перекрашивает тень сплошным цветом без альфы. Тени переименованы в
   нейтральное `shadow-lift` (глубина только за счёт тёмного), а приёмка получила проверку
   «имена теней не совпадают с именами цветов».
2. **Кислотные обложки.** Генератор арт-направления пересмотрен: приглушённые палитры вместо
   предельно насыщенных, убран фильтр-гало и «лучи» из центра, добавлены виньетка и нижняя тень —
   обложка читается как постер, а не как неоновая вывеска. Плашка выигрыша в колоде стала
   непрозрачно-тёмной, чтобы зелёный текст не тонул в арте.

**Прод-сборка проверена как артефакт**

- `npm run build && npm start` — так запущен текущий предпросмотр: все публичные и приватные маршруты отвечают 200,
  неизвестный путь отдаёт 404, оптимизатор изображений отдаёт SVG.

## 3. Осознанные отступления (§8 Части 5.1)

1. `DepositSheet` — один экран: методы и сумма на одном скролле, без шагов 1/2.
2. `GameDeck` встроена в порядок главной: у гостя — сразу после героя, у своего — после «Продолжить играть».
3. `WalletSwitcherSheet` группирует Фиат/Крипта; нулевые балансы внутри групп притушены, но не скрыты.
4. Кнопка «Играть» — на фронт-карте колоды, а не в отдельном блоке.
5. В табе «Профиль» у залогиненного — реальная аватарка.

## 4. Известные риски

- **`npm audit`**: 12 уязвимостей, 1 критическая — все относятся к `next@14.2.35` (DoS в оптимизаторе изображений
  с `remotePatterns`, RSC-DoS, контрабанда запросов в rewrites) и к транзитивным зависимостям Tailwind/ESLint.
  Исправление требует перехода на Next 16 (breaking). Остаёмся на 14 по решению по стеку; перед публичным
  деплоем стоит планировать миграцию отдельной задачей. Частичная защита уже есть: `remotePatterns` — явный
  список хостов без широких wildcard-ов.
- **Остаются разделы, которые можно улучшить без изменений в архитектуре:** sitemap не разделён на индекс
  и части (57 адресов), OG-картинка карточки игры рисуется на запрос (в прод-режиме кэшируется Next),
  hreflang не нужен — мультиязычность запрещена §24.
- **Браузера в среде разработки нет**: интерактив (жесты, анимации, скролл, фокус) и вёрстка 360–430 px
  проверяются глазами по сценарию из §2 выше, автотестами покрыты разметка и данные.

## 5. Заглушки и границы

- Мок-слой заменяет Части 2–4: реальные платёжные шлюзы, провайдерские сессии и модерация KYC не вызываются.
- Игровое поле — имитация (`MockSlotScreen`); в live-режиме запуск идёт в `/play/remote` c iframe провайдера.
- Push/email-уведомления и live-чат не реализуются по §24 — интерфейс их не обещает.
